### 建议设计

1. 沿用 POST /practices 和 POST /family/children/{child}/previews，扩展输入支持 allocations:[{pointId,total}]；保留旧 pointId/total 单点输入兼容。两种表示同时提供时拒绝，不能静默取其中一个。旧单点默认30题保持。
2. 新界面选择知识点后显示逐项题量和总量。初始单点30题；建议选择集合变化时按当前总量均分、余数按显示顺序分配，允许手工修改；具体交互待用户审阅。每项至少1、合计1—100，所选点数量超过总量时提示调整，不自动增加总量。
3. 服务端将合法输入统一为按pointId排序的分配，验证重复、整数、数量、当前年级及分类启用；前端校验只作提示，服务端为最终依据。相同分配仅顺序不同视为相同请求；旧单点历史幂等键继续可核对，不能因新哈希规则让旧请求冲突。
4. 普通组卷保留自身业务入口，不依赖错题seed。复用现有事务、稳定锁序、当前审核启用题池与 persistSnapshot；同一份无放回抽取，逐知识点精确满足，任何不足整份拒绝并说明各不足项所需/可用数。
5. 家长发送继续复查当前ACTIVE关联、预览15分钟、接收年级、全部分类和题目版本；题干与顺序固定，不在发送时重抽。切孩子/改配置清除旧预览，旧异步响应不得覆盖新孩子/配置。
6. 新配置变化才换创建键；同配置结果不明保持同键重试，不能因重新打开界面重复造卷。结果不明时不误报失败或成功。
7. 保存、接管、计时、提交判分、错题及逐题知识点统计沿用现有流程；历史快照和I3行为保持。
