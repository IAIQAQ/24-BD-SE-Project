# P3完整互动版实施方案草案

日期：2026-10-31。状态：大纲已由用户确认，详细执行计划已整理；尚未开始编码、生成素材或构建新包。用户已反馈P2体验无明显问题，P2作为本轮保留的可展示版本。

## 范围与实现路线

目标：在P2绘本视觉上加入角色动作、本次练习成长、完成反馈、可关闭音效和操作动效。仅学生学习流程增加陪伴表现，家长和管理员保留管理风格。长期养成、小花园、积分、签到、徽章、排行榜、奖励兑换、语音讲题不做。

推荐Vue状态驱动＋CSS局部动画＋本地轻音效。不引入动画框架或第三方音频服务，不改后端/API/schema。逐帧角色动画会增加绘制、素材一致性与适配工作；仅整张小芽上下浮动则无法充分表达成长和局部动作，因此推荐保留P2主体，少量增加分层叶片/装饰素材，由CSS控制轻微摆动。不承诺复杂骨骼动画、行走或角色口型。

## 具体效果与规则

| 模块 | 提议效果 | 触发与限制 |
|---|---|---|
| 首页角色 | 进入首页时短暂轻摆/呼吸，随后安静停留 | 每次进入一轮约2—3秒；不持续循环吸引注意，不延迟开始练习 |
| 本次练习成长 | 以小苗、舒展、长成三个阶段展示当前填写进度，配真实“已填写N/M题” | 由draft.items非空答案数计算；零题为初始、0至不足一半为第一阶段、一半至未满为第二阶段、全部填写为第三阶段；填完不代表答对或交卷成功 |
| 成长变化 | 阶段变化时叶片短暂展开，随后静止 | 同阶段内改答案不重复奖励；清空答案时按实际数量退回阶段，不维持虚假成长 |
| 保存反馈 | 沿用原保存状态，手动保存成功后图标短暂点亮 | 自动保存不反复播放音效；失败沿用错误说明，不显示成功动作；成长与是否已保存分别表达 |
| 完成反馈 | 正式交卷成功后，小芽短暂弹跳，少量叶片/星点庆祝和一句鼓励 | 仅提交结果确认完成触发，约1—2秒；成绩仍为重点；重复查看旧结果只展示静态鼓励，不重复庆祝或发声 |
| 轻音效 | 操作轻点、手动保存成功、正式完成三类短音；有明显开关 | 默认关闭，需用户主动开启；不播背景音乐、错题惩罚声或语音；刷新/下次本机使用记住开关，不向服务器存储 |
| 操作动效 | 按钮轻微按压、卡片选中和非答题页面短淡入 | 约100—180ms；不改变点击区、焦点和滚动，不让问题或输入框跳动；答题翻题立即响应 |

成长条位于原答题进度区域，使用紧凑图形和数字，不把大幅花园插画塞进答题中心。保留真实算式、输入、保存和交卷按钮位置。继续任务时从后端已保存答案重算成长，不用Summary.currentSeq推算已答比例；首页继续卡仍使用P2真实题号/状态文案。

音效关闭不能影响任何业务操作；浏览器限制、设备静音或音频初始化失败时页面仍正常，开关状态和提示应准确。页面退到后台后停止装饰动画/声音，返回不补播；保存与计时仍由现有逻辑负责。系统“减少动态效果”生效时改静态显示，不闪烁，不快速连续播放。

## 当前工程依据及改动边界

- useLearningApp已有answered计算、dirty/conflict、保存状态、确认交卷、提交核对、visibility生命周期；展示层消费这些信息，避免另造保存/计时状态。
- LearningApp、GardenHero、SproutCompanion、IllustratedPracticeCard及learning-ui.css承载互动；必要时新增一个紧凑成长组件及一个音效设置模块，具体文件拆分在实施前确认，不新增通用动画平台。
- 保存音效必须绑定本次手动保存成功事件，完成反馈绑定本次提交或核对最终成功事件；不通过监听“result页面出现”或保存文案猜测请求成功。重复点击/核对成功去重按真实练习ID处理，切换身份清除本轮反馈标记。
- 正在答题/交卷确认/核对与busy时，继续保留P2头像导航保护。异常、未保存、内容错误和冲突提示不被动画覆盖。
- 本机音效偏好为设备级设置，明确不随账号跨设备同步。开关在学生个人页与答题页非干扰位置可达，主操作区域不增加解释长文。
- 复用已有欢迎/完成角色；分层叶片和成长阶段所需少量素材在确认方案后制作，生成结果先检查风格和透明边缘。新增素材建议预算不超过约1MB，超出如实说明。
- 不改390题、11知识点、账号密码/年级、家庭关系、历史成绩与题目快照。不因新增音效或庆祝触发答题提交、改分或新增统计记录。

## 工时估算与实施顺序

以下是基于源码检查的初估，有效工作时间不等于连续等待时间，也不以P2实际耗时直接外推；日工时尚未确定。

| 批次 | 内容及交付点 | 初估 |
|---|---|---|
| 1 | 备份P2，整理本轮资源和触发规则，完成首页局部动作及按钮反馈，先看真实截图/短录屏 | 2—3小时 |
| 2 | 三阶段练习成长、填写/清空/保存恢复、异常状态协调与必要检查 | 3—5小时 |
| 3 | 一次性完成庆祝、轻音效与关闭开关、后台/重复触发/减少动态效果处理 | 3—5小时 |
| 4 | 网页流程回归、320/390/768适配、独立Android/Web包、说明与启动供用户体验 | 4—5小时 |
| 合计 | 实现与工程检查 | 12—18小时 |

另留3—5小时供素材返工、用户体验反馈和APP/Web差异调整；建议按15—23小时安排。若每天可投入4小时，约需4—6个工作时段/天，实际安排仍取决于每天工时。11月6日截止、11月5日公网试用目标与部署/换机交接任务会竞争时间，不能把全部剩余时间都用于P3；是否做满由用户决策，不默默删减已批准范围。

每批完成必要检查后交用户体验；未完成的P3不替换冻结P2交付。若范围变化，明确记录已完成与推迟项，不把部分版叫作完整互动版。

## 验收与独立产物

1. 首页角色局部动作、按钮反馈可见且不挡操作；答题不出现持续晃动角色。
2. 五题填写0/1/3/5题及清空答案时，数字和阶段准确；已填写不冒充已答对。保存退出、刷新/重新登录恢复后与已保存答案一致。
3. 保存失败、编辑冲突、未答确认、交卷失败和核对中不出现成功庆祝；成功确认完成后本轮仅触发一次。重新看旧成绩不重复发声。
4. 音效默认关，打开/关闭立即生效，本机偏好可恢复；不播放背景音乐，不因播放受限阻止操作。用户自行体验APP音效与静音效果，工程检查不能冒充已验证真机听感。
5. 后台暂停、返回不补播；减少动态效果时能完成同样学习流程；键盘焦点和可点击区域保留，按钮至少48px，320/390/768无遮挡/溢出。
6. 复用现有前端测试，增加成长边界、手动保存/提交触发去重、开关和失败回退检查；类型/Web/Android构建，体验库网页完成一条练习与家长任务回归。后端未改时不在体验库运行造数型全量验收。
7. 独立ui-p3-v1命名：APK、test.apk、Web ZIP、manifest；先检查同名是否存在，存在就使用新批次，不覆盖。保留P2/旧包和源码备份，按工作区指纹定位，不自动暂存/提交/上传/部署。
8. 数据与旧包前后核对，专属dev-window-progress记录每批结果；APP只按用户要求安装打开，不自动做模拟器验收。工程检查完成与用户体验通过分别记录。
