# P2视觉修订idea V2：以B方案整体画面为目标

日期：2026-10-30。状态：整页视觉修订及本机工程检查完成，用户视觉体验确认待反馈。本修订替代此前“只加两张小芽即可完成B视觉”的理解，保留P1业务与当前可运行版。

## 目标和当前差距

用户认可P1业务，但指出ui-p2-v1与已选B1示意图明显不同。本次目标是接近B1的整体视觉：花园场景横幅、突出的小芽、舒展标题、绘本式任务卡、鼓励区及统一导航。B2用于错题页的协调参考。测试通过只证明功能检查通过，不替代视觉对照。

当前不足：纯色卡片旁的小图片替代了场景；标题挤成两行；练习仍为普通图标卡片；顶部头像/年级信息及底部鼓励未统一。修订必须处理布局和素材两部分。

## 按区域实现

| 区域 | 实现目标 | 实现方法 |
|---|---|---|
| 顶部 | 小芽标志、品牌、年级标签、圆形插画头像 | 复用welcome图作标志；年级来自profile.grade，只读标签；通用插画头像进入现有“我的”，退出登录移至现有个人页并保留入口 |
| 问候 | 昵称突出、少量暖黄装饰 | Vue显示真实昵称；装饰不携带数据，长昵称自然换行，不裁掉姓名 |
| 主横幅 | 约2:1的花园卡片，大号小芽在右，标题/短句/按钮在左 | 一张不含文字/角色的花园背景＋现有透明小芽＋真实HTML文字和按钮；CSS Grid控制内容和角色占位 |
| 练习卡片 | 左侧绘本/铅笔插画，中间短标题和状态，右侧操作 | 复用records及原点击事件；父任务仍显示“家长安排”和练习类型，知识点长名称放次要行/可展开详情 |
| 继续练习 | 清楚显示“继续上次练习”与保存状态 | 仅由IN_PROGRESS记录触发；不根据currentSeq伪造已答比例 |
| 底部鼓励 | 小芽与短气泡，少量草叶装饰 | 复用complete插画、真实HTML鼓励语；位于内容流内、导航上方，不固定覆盖列表 |
| 导航 | 圆角底栏、统一图标和清楚选中态 | 沿用P1四入口及UiIcon；保留安全区与键盘焦点 |
| 错题页 | 小芽页头、清楚大算式卡片和短操作 | 参考B2，但继续保留跨页选择、历史年级分组、原题重练/同类强化；不新增示意图筛选器 |
| 结果与空状态 | 与首页角色、配色一致 | 复用现有完成/欢迎图，调整比例和底色；原成绩、解析及异常提示保留 |

### 主横幅的具体排版

- 手机390px为主要对照尺寸，内容卡片随页面宽度自适应；目标高度约180—210px，横向构图，不用“纵向小芽组件＋长标题”硬挤。
- 左侧约55%—60%，包含“一起练口算”“小芽陪你想一想”和“开始练习”；右侧约40%，角色明显大于当前128px组件在卡片中的视觉占比，底部贴近花园。
- 标题在320/390px均按完整词句显示，不出现“一起练口／算”或强行“一起／练口算”。字号随可用宽度调节，按钮至少48px高。
- 背景可以裁切，但文字、按钮和角色单独排版，不随背景缩放。花叶可以叠在边缘，不能挡住内容或焦点。
- 桌面仍保持移动端产品的中心内容区，不把主插画放大成全屏，也不新增后台布局。

## 数据和交互约束

- 一份记录就是一份真实记录，不为了凑示意图的两张卡而隐藏其他任务。列表保留原分页，不增加额外网络请求或改变顺序。
- PENDING显示“开始”、IN_PROGRESS显示“继续”、COMPLETED显示“看结果”，WITHDRAWN/VOID显示其真实状态，事件仍走原resume/showResult。
- 当前Summary只有currentSeq，没有可靠的已答数。继续卡显示“上次看到第N题 / 共M题”或“已保存”；不照搬示意图的2/5苗芽完成进度。若要显示真实已答进度，另行讨论接口需求，不作为本次前置条件。
- 顶部年级不做快捷改级下拉；改级仍在原个人资料页。头像是通用插画，不新增上传或真实儿童照片。
- 三年级长知识点可完整展开查看，不能只留“加法/乘法”导致知识点含义丢失。预览接收人、内容错误、编辑冲突及未保存/交卷确认不折叠隐藏。
- 不改变390题、账号密码/年级、历史结果、家庭关系、API、后端和schema。家长/管理员沿用现状，不把儿童插画铺到管理表单。
- 全部静态，无动效、声音、积分、签到、勋章或长期成长状态；这仍是P2视觉修订，不进入P3。

## 素材清单与使用

复用：现有welcome/complete角色，保留原图和旧包。

新增四份独立素材：

1. garden背景：草地、灌木、云、少量花朵，横向构图，左侧留文字空间；不含角色、文字、按钮。
2. task-notebook：笔记本和铅笔，用于家长/待完成任务卡；封面不画可被当成真实题目的算式。
3. continue-book：打开的练习本，用于继续/结果卡；同样不烘焙题干或成绩。
4. avatar：通用儿童插画头像，只作默认视觉，不建立用户上传能力。

使用内置imagegen生成；生成图不是网页截图，不直接拿整张B1铺成背景。素材落`frontend/src/assets/sprout/p2-scene/`。实施阶段对图片做尺寸压缩/WebP转码，保留本机生成原图；这是一次性素材准备，不新增运行时图片处理或打包框架。目标新增资源合计不超过约1MB，达不到时记录实际大小，不虚报压缩达标。

现有两张PNG可在保留原图后生成较小使用副本，避免继续叠加大图；素材缺失时背景退回纯色、图标/头像有简单占位，功能仍可操作。所有文字仍是HTML。

## 执行顺序和交付点

1. **素材和首页主体**：先做背景及卡片插画，完成header、横幅、真实记录卡、底部鼓励。先保存390px参考图/实际截图对照；主视觉相近后再继续其他页，不以零散素材完成作为阶段成功。
2. **协调错题/结果/空状态**：复用同一套角色和图标，保持答题页干净；补充320/390/768px及长昵称、多条记录、空状态检查。
3. **同版检查和体验包**：前端测试/类型/Web/Android构建，关键网页流程检查，独立`ui-p2-v2`产物；只安装打开APP供用户体验，不自动模拟器验收，不提交上传。

工程初估6—10个有效小时，素材返工会增加时间；不是完成日期承诺。先完成首页对照再扩到其他页，比再次一次性交付风格偏差更容易纠正。当前P1和ui-p2-v1均保留作为可运行版本。

## 视觉验收标准

- 对照B1：顶部信息层次、横向花园卡片、大号右侧角色、左侧标题按钮、绘本卡片、鼓励区、底栏这七项均有对应实现；不是仅“颜色相近＋放一张角色图”。
- 对照B2：错题页有协调的插画页头、大算式和选中状态，解析/历史仍能查看，原操作路径完整。
- 截图使用同一390px宽度及相似可见区域比较；另外提供320/768px检查。字体可因系统不同略有差异，不用“像素级一致”作虚假保证。
- 昵称、年级、成绩、题数取真实数据，旧记录完整保留；不为截图伪造任务、进度或清空账号。
- 按钮至少48px高，不被插画遮挡；图片失败仍能继续，安全区和导航不覆盖最后一张卡。
- 最终由用户对视觉与操作体验确认；自动测试和代码审查不能替代该确认。
