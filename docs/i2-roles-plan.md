# I2 注册、家长与管理员实施记录

2026-10-28。用户明确要求继续实现公众注册、家长端及管理员后台，随后询问当前测试密码；该询问不取消开发请求。沿用已经确认的需求报告与APP页面结构中的三角色流程，不重新启动平台选型或角色范围审批。

## 已有设计与本轮落点

统一账号、统一后端，Vue/Capacitor两端共享角色页面；管理员界面适合浏览器操作，也保留APP入口。公众只注册学生或家长，管理员由本机私有配置初始化。现有两个学生账号和I1记录保持。

1. 公众注册与档案：登录名唯一、必填校验、标准密码哈希；注册成功后登录，按真实角色分流；学生昵称/年级可修改，练习保存原年级。无手机号、短信、第三方登录和公众管理员注册。
2. 家庭关系：家长用学生登录名申请，学生确认或拒绝；多对多关联，解除需确认。待确认无数据权；解绑后下一次查询/发送/撤回/旧链接失权，学生已有有效任务保留。
3. 家长任务：选孩子、配置题量、预览固定实际题干、确认发送同一份；发送防重复、待完成/开始/完成/撤回状态；仅当前关联且发送本人能撤回尚未开始任务；家长只能看进度/结果/错题与基础学情，不能替学生答题。
4. 管理：题目和知识点查询/新增/修改、核对/启停、基础统计；数学内容改动重新核对。正常改题不改旧快照。确认数学错误时，相关未完成练习整份作废，完成记录标记且不重算，需与提交使用相同练习行锁。
5. Excel：业务列模板、上传检查、逐行反馈、整批拒绝/确认导入与幂等；新增内容默认待核对，不直接启用。保持整数答案子集，不借新后台声称已覆盖所有年级教材。

## 顺序与测试

- R1：注册/角色/档案/初始化管理员，拒绝公众ADMIN、越权学生接口；旧登录回归。
- R2：关系申请确认解绑、固定预览发送/撤回，测试未确认与解除后访问拒绝、旧任务保留、开始撤回互斥。
- R3：管理员维护、数学错误处置与原结果保留，测试普通用户拒绝、重审、错误作废；补导入整批拒绝与重复确认。
- R4：三角色Vue页面与真实接口联调，再模拟器新包；原学生完整流程继续回归。
- R5：实际验收、私有数据备份、本地提交；失败与未测单列，不把写完页面当验收完成。

## 数据与安全约束

使用追加迁移，不重写V1—V3；家长档案独立，学生档案保留；关系与业务操作持久化。角色鉴权放服务端，父母读取每次重查当前关联，公共注册不能创建ADMIN。私有管理员密码不写源码/APK/公开文档。

家长预览记录有归属和幂等键，不把未确认预览显示为学生任务；确认发送重新校验关系与内容可用性。关联→题目/预览→练习的锁顺序固定，普通题目更新和题目错误处置区别处理。

需要保留的范围限制：本机HTTPS与模拟器验证，不自动购买或发布；真实儿童/家长试用、教材逐页/人工内容审核、完整题型与强化仍是独立事项。管理员不能改学生成绩，无教师班级功能。
